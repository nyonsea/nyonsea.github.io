# Oracle Database移行検証環境 構築作業日報

**作業日：2026年11月13日**

## 1. Oracle Database検証環境の構築

### （1）PDB作成
- Oracle Database 19c環境に、検証用PDBを3つ作成。
- `MIGPDB1`、`MIGPDB2`、`MIGPDB3` の作成およびOPEN状態を確認。
- 今回のデータ作成・検証には `MIGPDB1` を使用。

### （2）スキーマ・ユーザー作成
- 業務データ所有者として `APP_OWNER` を作成。
- バッチ処理用 `APP_BATCH`、帳票・参照用 `APP_REPORT` を作成。
- 各ユーザーに必要なシステム権限および表領域クォータを設定。
- 過剰な管理権限を付与しない構成とした。

### （3）APP_OWNERのオブジェクト作成
- 業務データを想定した10テーブルを作成。
- シーケンス、主キー・外部キー等の制約、索引を作成。
- CLOB・BLOBを含むLOB格納構造を構築。

### （4）テストデータ投入
- マスタ、受注、明細、入金、出荷、監査ログ等のテストデータを作成。
- 合計171,530件のレコードを投入。
- CLOBデータ5,000件（各2,000文字）を投入。
- BLOBデータ1,000件（各32,768バイト）を投入。

### （5）データ検証
- 受注・明細間の金額整合性および参照整合性を確認。
- CLOBの日本語データについてUnicode表現を確認。
- BLOBの格納サイズおよび先頭・末尾バイトを確認。
- TABLE、INDEX、LOBSEGMENT、LOBINDEXの格納状況を確認。

**APP_OWNERの使用状況**
- 表領域使用量：約139.88MiB
- 設定クォータ：300MiB
- 残りクォータ：約160.13MiB

## 2. ネットワーク構築方針の見直し

当初は、自宅マンション付属Wi-Fi配下にあるOpenWrtを利用した外部接続構成を検討。

しかし、マンション付属Wi-Fiの二重NAT・動的IP環境では、外部からの直接接続やポートフォワーディングに制約があるため、当初想定したネットワーク構成の実現性に課題があると判断。

このため、OpenWrtに依存した接続方式に固執せず、Azure上に極小構成の踏み台VMを構築する方式へ方針を変更することとした。

踏み台VMを経由して検証環境へ接続する構成とし、外部公開範囲を抑えながら安全なリモート接続を実現する方向で設計を進める。
